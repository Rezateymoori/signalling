# سرور آزمایشی Signaling برای DirectChat

این سرویس فقط پیام‌های هماهنگی WebRTC (offer/answer/ICE) را در لحظه به کاربر آنلاین مقصد منتقل می‌کند. هیچ دیتابیس، تاریخچه پیام یا ذخیره‌سازی پیام چت ندارد و محتوای دریافتی را لاگ نمی‌کند.

## استقرار آزمایشی در Render
1. پوشه `signaling` را در یک مخزن GitHub قرار دهید (یا محتوای آن را در ریشه یک مخزن جداگانه بگذارید).
2. در Render یک Web Service از مخزن بسازید و Root Directory را `signaling` قرار دهید.
3. Render از `render.yaml`، فرمان نصب و اجرا را می‌خواند. آدرس HTTPS سرویس را نگه دارید؛ WebSocket متناظر با `wss://HOST/ws/CODE` است.
4. این سرویس فقط وقتی کاربر آنلاین است او را در حافظه همان پردازه می‌شناسد. با راه‌اندازی مجدد یا خواب سرویس، نشست‌ها از بین می‌روند.

## پیام‌های پروتکل
پس از اتصال، سرور `{"type":"ready","code":"..."}` می‌فرستد. کلاینت می‌تواند `offer`، `answer` یا `ice` با فیلدهای `to` و `payload` بفرستد. سرور آن‌ها را فقط به WebSocket آنلاین مقصد رله می‌کند.

## محدودیت امنیتی و عملکردی
این فقط زیرساخت Signaling است، نه پیام‌رسان کامل. برنامه اندروید فعلی هنوز به این پروتکل وصل نشده و هنوز WebRTC DataChannel، احراز هویت واقعی کدها، تأیید کلید مخاطب و رمزگذاری سرتاسری پیام‌ها را ندارد. بنابراین تا تکمیل و آزمون کلاینت، برای پیام خصوصی استفاده نکنید. HTTPS/WSS رمزگذاری مسیر تا سرور را فراهم می‌کند، اما به‌تنهایی E2EE نیست.
